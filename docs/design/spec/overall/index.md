# 整体设计

NextSWITCH 平台的总体架构设计，包括服务拓扑、通信协议、端口分配和跨服务约定。

## 平台架构概览

NextSWITCH 采用微服务架构，各服务通过 gRPC 和 Redis Pub/Sub 进行通信，由 API 网关统一对外暴露 REST 接口。

### 端点接入协议对照

| 端点类型 | 协议 | 接入服务 | 端口 | 说明 |
|---------|------|---------|------|------|
| 客户 SIP 网关 / PSTN 中继 | SIP (UDP/TCP/TLS) | sipserver | 5060-5061 | 传统电话线路接入 |
| 客户 WebRTC（浏览器/小程序） | WebSocket + WebRTC | sigserver | 5443 | 网页一键拨入 |
| 座席 SIP 硬电话 | SIP (UDP/TCP/TLS) | sipserver | 5060-5061 | 物理 IP 话机 |
| 座席 WebRTC 话机 | WebSocket + WebRTC | sigserver | 5443 | 浏览器/App 软电话 |
| 座席软电话条 | WebSocket (JSON-RPC) | cti-server | 8083 | 呼叫控制 + 状态推送 |

## 核心服务

| 服务 | 职责 |
|------|------|
| **sipserver** | SIP 信令：代理、注册、B2BUA、呼叫路由 |
| **sigserver** | WS/WSS 信令：WebRTC 媒体协商、WebSocket 私有协议接入 |
| **medserver** | 音频处理、录音、会议、IVR、呼叫处理（ProcessCall） |
| **cti-server** | 坐席状态机、呼叫控制、ACD 分配 |
| **im-server** | 即时消息、全渠道接入、AI 集成 |
| **config-service** | 配置数据管理、版本控制 |
| **nextswitch-api** | API 网关、统一入口 |
| **auth-service** | 认证授权、JWT 签发 |
